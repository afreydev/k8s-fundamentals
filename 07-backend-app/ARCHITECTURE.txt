==============================================================================
  REQUEST FLOW  (curl $URL/visits)
==============================================================================
  1. curl hits node IP :30085              → NodePort forwards to Service
  2. backend-service picks a pod           → app=backend, round-robin
  3. pod reads DB_HOST/DB_USER/DB_PASSWORD → from Secret backend-db-secret
  4. postgres-service DNS resolves         → postgres-0.postgres-service →
                                              current pod IP of postgres-0
  5. row written to the data directory     → PVC postgres-data-postgres-0

==============================================================================
  WHY TWO CONTROLLERS
==============================================================================
  Deployment  (backend)        StatefulSet  (postgres)
  ─────────────────────        ───────────────────────
  pods interchangeable         pods have identity: postgres-0 ≠ postgres-1
  no persistent storage        1 PVC per pod, survives restarts
  scale / restart any order    ordered: 0 → 1, teardown 1 → 0
  one Service VIP              per-pod DNS via headless Service
  ask: "how many copies?"      ask: "which one am I?"

  Rule of thumb: if losing the pod's name or disk matters, it's a StatefulSet.
